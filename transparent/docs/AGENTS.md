# Transparent PIR documentation maintenance

Read README.md first. Keep target parameters in deployment.md, observed state in
status.md, milestone definitions and unchecked work in remaining-work.md, and
measurements under ../evidence/. contract.md defines requirements,
not implementation claims. Delete superseded prose and update inbound links;
do not create archive copies or forwarding stubs.

Retain acceptance data, relevant failures, unresolved incidents and their input,
source and configuration provenance. Superseded diagnostic bundles may be deleted
when no retained claim or executable fixture depends on them; record the reason
and pre-deletion Git revision. Retained raw artifacts stay byte-for-byte immutable.
Never promote historical partial-journal or research-backend results to full-chain
wallet capacity. Do not claim live verification from code alone.
