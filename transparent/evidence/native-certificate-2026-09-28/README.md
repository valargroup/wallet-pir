# Native correctness screen for Transparent shapes, 2026-09-28

Correctness-noise reports for the native ReinspiRING two-mask m29 profile
(d=2,048, q=2^54, p=2^16, two-limb Gaussian `K_g` with 19-bit limbs, masks
rounded to 29 bits, 49-bit query, 22-bit response) at the row counts Transparent
uses, schema `transparent-shard-v8`. No published v8 segment exists yet, so
**none of these is a per-snapshot certificate** of a served segment. They screen
shapes and exercise the tool that will produce those certificates.

## Method

- Report tool: `transparent/services/transparent-shard-server/examples/native_certificate.rs`,
  modelled on Enhance's `native_certificate` example. It rebuilds the hint and
  two-mask preprocessing with `reinspiring::native::NativePreprocessed::build_two_mask_analyzed`
  and emits `native-noise-two-mask-rounded-v1`. In segment mode it binds to a
  snapshot when given `--public` or `--public-sha256`; the unit test
  `runtime::tests::masks_rebuilt_from_row_bytes_equal_the_served_masks` checks
  that its row-bytes derivation equals the server's published masks.
- Checker: `reinspiring/tools/security/certify_native.py` from ipir-sp
  `v0.1.0-rc.6` (commit 1f2aec6), default `--require-bits 128`. Its certificate
  is conditional on the exported weights and idealised sampler draws; it is not
  a lattice-security estimate.
- Command: `transparent/evidence/native-certificate-2026-09-28/run.sh <certify_native.py>`
  (release profile). Source: branch `native-transparent`, parent commit
  c9d165a1 plus the example. Host: Apple M4 Max, 128 GiB, macOS; each report
  took at most 1.6 s of analysis.
- `synthetic` mode uses a table-shaped setup named `certificate-synthetic`
  (masks distributed as the served ones but not equal to them) and the
  **worst-case query term** for any u16 column of that height (L1 = 65,535 x
  rows). The packing weights depend on the hint and so on the data; they are
  measured for a splitmix64 full-range database (`random`, seed 1) and an
  all-0xffff one (`max`). The query term is data-independent; the packing term
  is not, so these are representative, not bounds for every database.
- `segment` mode on `archive-wide` pages uses a reproducible pseudo-random
  65,536 x 4,096-byte table (`random.Random(1).randbytes`, regenerated by
  `run.sh`, not retained) with the query term **measured** from its columns.

## Results

Certified failure bits (`certified_failure_bits`; 128 required):

| Rows | synthetic random | synthetic max | Max deterministic error |
|---:|---:|---:|---:|
| 2,048 | 294 | 289 | 4,567,564,288 |
| 4,096 | 280 | 287 | 6,715,015,168 |
| 8,192 | 270 | 259 | 11,009,916,928 |
| 32,768 | 173 | 173 | 36,779,327,488 |
| 65,536 | **83** | **83** | 71,138,541,568 |

Segment mode, `archive-wide` pages (65,536 rows), measured query term
(L1 2,162,751,950): **170 bits**, meets 128.

The worst-case query term fails 128 bits at 65,536 rows (it meets 78). The
deterministic 49-bit query rounding contributes 16 x L1 = 68.7e9 against a
decryption radius of 2^37 = 137.4e9, so half the budget goes to a column that
is 0xffff in every row. Packing weights barely move with the data (L1 about
4.7–5.1e10 for every shape).

## Limits and consequences

- A served `archive-wide` page segment (the only 65,536-row table in the
  registry) cannot be accepted on the data-independent bound. It needs a
  per-snapshot certificate with the measured query term, which the segment
  mode produces; real page tables are sparse, so their column L1 should sit far
  below the random table's. That run belongs to the first v8 publication.
- 32,768-row tables (`archive-32k`, and both `archive-wide` directories) pass
  the worst-case bound with 45 bits of margin; recent tables with more.
- Nothing here measures decryption failures; it is the analytic screen only.
- The ipir-sp checker version is part of the result; re-run on any
  reinspiring or profile change.

Files: `synthetic-<fill>-<rows>.report.json` and `.certificate.json` for each
shape, `segment-measured-archive-wide-pages-seed1.*`, `run.sh`, and
`SHA256SUMS` over the retained outputs.
