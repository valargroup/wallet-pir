# Vizor PR #601 mainnet wallet exercise

This is a local operator check of chainapsis/vizor-wallet PR #601 at
`edbe5663f698e10a9d21f81ff52b7d2da17701dc`. The operator-provided `m11`
mnemonic was read only at runtime from a local owner-only file. Neither the
mnemonic, derived addresses, transaction identifiers, nor wallet database are
included in this evidence. The local-only Rust integration harness and wallet
database are excluded from Git and remain in owner-only temporary storage.

The first fresh mainnet import used birthday height 3,490,000 and the Vizor
default lightwalletd endpoint. It scanned through height 3,494,244 and then
resumed successfully, but found zero transactions and zero private recovery
work. This was not a PIR acceptance test.

The canonical node maps 2026-08-01 00:00 UTC between block heights 3,432,059
and 3,432,060. A second fresh import used birthday 3,432,000, scanned through
height 3,494,247 and ran a second sync. The harness completed successfully. The
wallet database contained 163 transactions and 557 Ironwood received notes;
the metadata queue fell from 120 to zero. Its recovery status after the first
sync was zero queries, zero rediscovery jobs, 790 suspended obligations; after
resume those counts were unchanged. The outgoing queue also contained 790
entries, all marked not recoverable. The residual service phase after the first
sync was `waiting_for_snapshot`, but the final work reader reported no
query-ready positions. There is no evidence of a successful PIR query or
authenticated private record retrieval from this wallet state; request-level
client telemetry was not captured.

The pinned wallet library can set `not_recoverable` after applying a PIR result
or while suspending outgoing work that has no matching funding account during
database initialization or account removal. The final queue count cannot
distinguish those paths. It is not evidence of 790 successful private queries
or of 790 failed transactions.

This confirms that the pinned PR branch can import, scan and resume this wallet
on mainnet. It does **not** pass the required live restore/resume/reorg acceptance
over public PIR HTTPS. That gate remains open until a wallet with query-ready
work and controlled reorg evidence is exercised. No on-chain transaction was
created during this check.
